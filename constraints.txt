# Jellyscope - the versions of what the dependencies pull in
#
# requirements.txt names what the application uses, each at one version.
# Those packages need packages of their own (FastAPI needs pydantic, httpx
# needs certifi, uvicorn needs h11 ...), and they ask only for "this version
# or newer". Left like that, a new installation gets whatever is newest that
# day - a combination nobody tested - and no update touches them again: an
# installed package satisfies "or newer" for ever, so a fix in one of them
# would never reach a server installed long ago.
#
# This file gives each of them one version, the one the tests ran with.
# requirements.txt refers to it (-c constraints.txt), so every
# `pip install -r requirements.txt` honours it: deploy/install.sh,
# deploy/update.sh, the Update button in the app (its dry run too) and the
# Docker image. pip then also moves an installed package to the version
# here. A constraint installs nothing by itself, it only says which version.
#
# One version, one place: a package of requirements.txt is pinned there,
# not here. Development tools (ruff, rope ...) do not belong here either.
#
# Changing a version: build a fresh .venv from requirements.txt, run the
# tests, and take the versions from `.venv/bin/python -m pip freeze`.
# tests/test_deploy.py checks that every package the requirements pull in
# is here, at the version installed.
